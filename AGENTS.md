# AGENTS.md — `hivemind-plugin-manager`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

HiveMind Plugin Manager (HPM) is the entry-point loader for the HiveMind
ecosystem: it defines the abstract base classes and factories for database
backends, network protocols, agent protocols, binary data handlers, and
admission-policy plugins, and discovers concrete implementations via
`importlib.metadata` entry points (`hivemind.database`,
`hivemind.network.protocol`, `hivemind.agent.protocol`,
`hivemind.binary.protocol`, `hivemind.policy`). Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core), which
consumes these base classes and factories at runtime. Concrete plugins that
implement these interfaces: `hivemind-json-db-plugin`,
`hivemind-sqlite-database`, `hivemind-redis-database` (database),
`hivemind-websocket-protocol` (network), `hivemind-ovos-agent-plugin` (agent
protocol), `hivemind-audio-binary-protocol` (binary). Because this repo
defines the interfaces, changing a base class's method signature or a
`Client`/`Verdict` field is a cross-repo contract change — grep every
consumer plugin before editing `AbstractDB`, `AbstractRemoteDB`,
`NetworkProtocol`, `AgentProtocol`, `BinaryDataHandlerProtocol`, or
`PolicyPlugin`.

## Layout / build / test

- Package module: `hivemind_plugin_manager/` (`database.py`, `policy.py`,
  `protocols.py`, `tui.py`, `version.py`). Tests live in `tests/` (unit) and
  `tests/e2e/` (resolves real published plugins through the factories into an
  in-process `hivescope` hive — needs the `test` extra installed, no live hub
  required). Do not create a second test directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests -q`.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Working agreement (org-wide law)

- **Git identity is always** `JarbasAi <jarbasai@mailfence.com>`. Never set a
  per-repo override.
- **Never push `dev` or `master`.** Work on a feature branch and open a
  **draft** PR into `dev`. A human merges. You do not merge your own PRs.
- **Never merge or modify `Release X → master` PRs.** They are the maintainer's
  stable-release mechanism, generated by automation.
- **One commit per PR** (squash before pushing). Conventional commits; `feat:`
  only for a user-visible new capability. `fix:`, `docs:`, `chore:`, `ci:`
  otherwise.
- **Disclose AI authorship.** Every PR/issue/comment an agent writes carries, at
  the top: `> 🤖 Auto-generated by <model> via Claude Code — NOT human-reviewed.
  Verify before acting.` PR bodies are plain human prose (3–6 short paragraphs),
  no tables or section-symbol spray.
- **Never edit someone else's** issue, PR description, or comment. Add a comment
  instead; on your own PRs, edit the body rather than piling on comments.
- Keep durable text (README, docs, PR bodies, comments) timeless and standalone:
  no dates, no "currently/now/new", no meta-commentary about the edit itself.
- No scratch files, committed virtualenvs, `__pycache__`, `.pyc`, `.egg-info`,
  or build artifacts in a PR. `git show --stat` shows only intended files.

## Dependencies

- **Floor pins only** (`>=X.Y.Za1`), bumped when a feature or fix is actually
  needed — with a one-line comment saying why. No upper caps unless a specific
  released version is genuinely broken (say which and why). The `test` extra
  in `pyproject.toml` already documents why its floors are prereleases (they
  let a plain `pip install .[test]` resolve the 2.x HiveMind stack).
- **No lockfiles, ever.** Target the latest alphas (`--prerelease=allow`).
- Runtime deps live in `requirements.txt` (pulled in dynamically via
  `pyproject.toml`); metadata and the `test` extra live in `pyproject.toml`.
  Never install from git — depend on a published PyPI alpha.
- Apache-2.0. Do not add GPL/AGPL dependencies.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This is the interface repo: `AbstractDB`/`AbstractRemoteDB`
  (`database.py`), `NetworkProtocol`/`AgentProtocol`/
  `BinaryDataHandlerProtocol` (`protocols.py`), and `PolicyPlugin`/`Verdict`/
  `Mutation` (`policy.py`) are the contracts every backend plugin subclasses.
  Changing a method signature, a default, or a `Client` field is a breaking
  change for every downstream plugin listed above — grep them first, and fix
  and merge them before landing the base-class change here.
- `PolicyPlugin.review()` is documented and implemented as fail-closed: an
  exception during review must surface as `Verdict.deny("policy_error", ...)`,
  never a silent allow. Preserve that behavior in any change to the review
  chain runner; `observe()` exceptions are logged and swallowed by design
  (observation is not an admission decision).
- `Client.serialize()`/`Client.deserialize()` (`database.py`) must round-trip
  every ACL-relevant field (identity, blacklists, `can_broadcast`, and any
  field added later) — a field that survives one direction but not the other
  is a silent ACL bypass or a silent lockout. Add or change a `Client` field
  only alongside a serialize/deserialize round-trip test.
- `AbstractDB` documents that backend-specific errors "must fail loudly
  instead of being silently downgraded" — a database plugin swallowing a
  backend error and returning a default is the fail-open bug this repo exists
  to prevent; don't add code here that masks one.
- `AbstractDB` provides a default cache-invalidation hook that backends can
  override for targeted invalidation; any cache added on the client/ACL
  resolution path needs an identity guard and must invalidate on every write,
  not just on read.
- `hivemind-ovos-agent-plugin` and `hivemind-json-db-plugin` (and other
  `hivemind.agent.protocol` / `hivemind.database` entry points) are the
  concrete plugins resolved through `AgentProtocolFactory` /
  `DatabaseFactory`; agent plugins are the modern replacement for solvers
  (`opm.agents.chat`) — do not add new solver-based code paths here.
- `hpm` (the `tui.py` console script) is a thin discovery/inspection CLI over
  `find_plugins`; keep it read-only against installed plugins, it is not a
  place to grow admission logic.
